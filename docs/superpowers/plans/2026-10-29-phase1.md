# WoA Rescue Kit — Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a host CLI that produces a bootable WinPE ARM64 USB/ISO with Snapdragon drivers, and a Win32 rescue GUI that safely views and changes disks from inside WinPE.

**Architecture:** A Cargo workspace with three library crates and two apps:
- `diskcore` (pure model, operations queue, validation, apply runner over a `Backend` trait);
- `drivers` (INF parsing, PE audit, selection);
- `winstorage` (Storage Management WMI, virtdisk, BitLocker WMI, process runner, logger);
- `woa-builder` (CLI);
- `rescue` (GUI).

Everything that decides anything is pure Rust with unit tests. Windows calls are thin and covered by admin-only VHDX integration tests.

**Tech Stack:**
- Rust stable, MSVC targets `x86_64-pc-windows-msvc` and `aarch64-pc-windows-msvc`.
- Crates: `windows` (Win32, COM/WMI, virtdisk, GDI, controls), `clap` (derive), `serde` + `serde_json`, `thiserror`, `anyhow` (apps only), `embed-manifest` (build dependency for `rescue`), `tempfile` (dev).
- External tools: Windows ADK + WinPE add-on (copype, ADK DISM), `bcdboot`.

**Spec:** `docs/design/2026-10-29-phase1-design.md` (read it alongside this plan). Project memory: `brain.md`.

## Global Constraints

- All UI text, log text and docs in **British English**.
- Everything placed inside WinPE must have PE header machine `0xAA64`. This one check accepts ARM64 and ARM64X; ARM64EC images report `0x8664` and are rejected.
- `rescue.exe` must not depend on .NET, WinRT, WinUI, WebView2 or emoji fonts. Use plain Win32, comctl32 v6 and GDI with `DEFAULT_GUI_FONT`.
- The Phase 1 disk operations are Create, Delete, Format (NTFS, FAT32 ≤ 32 GiB, exFAT) and Resize (NTFS only). There are no raw sector writes.
- New partitions are aligned to 1 MiB (`1_048_576`).
- Locked BitLocker volumes, the boot media, the running OS disk (desktop) and physical disks in simulation mode are never written to.
- WinPE locale: `/Set-AllIntl:en-GB`, `/Set-InputLocale:0409:00000409`, `/Set-ScratchSpace:512`.
- USB writer: bus type must be USB, the disk must not be the running OS disk, and size ≤ 256 GiB (`274_877_906_944`) unless `--force-large`. The user must type the disk number again to confirm.
- Recovery keys are never written to logs.
- Personal-use project: no signing, installer or licence work.
- Commit after every task. The repo is local only; never push.

## Review Focus

1. **Disk renumbered between view and Apply** (USB re-plugged). Operations address disks by `DiskId` (MSFT_Disk `UniqueId`) and never by number; Apply re-snapshots and refuses if the id is missing. Test is in Task 3.
2. **Partitions without a drive letter** (ESP, recovery, fresh partitions). Operations address partitions by disk plus `offset`, never by letter. Test is in Task 3.
3. **Backend failure mid-queue** (dirty volume refuses to shrink). The runner stops, reports completed, failed and not-run operations, and runs nothing after the failure. Test is in Task 3.
4. **Paths with spaces and non-ASCII** (the real driver folder is `E:\ClaudCode windows\Snapdragon Qcom Drivers`). Arguments are passed as separate `OsString`s and never concatenated into one command string. Tests are in Tasks 5 and 6.
5. **Running `rescue.exe` on the desktop outside simulation.** The running OS disk is read-only (`Rule::RunningOs`). Tests are in Tasks 3 and 8.

### Task 3: diskcore operations queue, validation and apply runner

**Files:** Create `crates/diskcore/src/{ops.rs,validate.rs,apply.rs}`.

**Interfaces — Consumes:** Task 2 types. **Produces:**
```rust
pub enum Op {
    Create { disk: DiskId, offset: u64, size: u64, fs: FsKind, label: String },
    Delete { disk: DiskId, offset: u64 },
    Format { disk: DiskId, offset: u64, fs: FsKind, label: String },
    Resize { disk: DiskId, offset: u64, new_size: u64 },
}
impl Op { pub fn describe(&self, disks: &[Disk]) -> String }   // British English, e.g. "Shrink C: by 40.0 GB"
pub struct Context { pub simulation: bool, pub allow_system_partitions: bool }
pub enum Rule { UnknownTarget, Overlap, OutOfDisk, LockedVolume, BootMedia, RunningOs,
    PhysicalInSimulation, SystemPartition, BelowSupportedMin, AboveSupportedMax,
    ResizeNotNtfs, ExtendNotAdjacent, Fat32TooLarge, Misaligned }
pub enum Severity { Error, Warning }
pub struct Issue { pub op_index: usize, pub rule: Rule, pub severity: Severity, pub message: String }
pub struct Validation { pub issues: Vec<Issue>, pub projected: Vec<Disk> }
impl Validation { pub fn ok(&self) -> bool }                     // no Error issues
pub fn project(disks: &[Disk], op: &Op) -> Result<Vec<Disk>, Issue>;  // Create offset aligned up to MIB here
pub fn validate(disks: &[Disk], queue: &[Op], ctx: &Context) -> Validation;
pub trait Backend { fn snapshot(&mut self) -> Result<Vec<Disk>, BackendError>;
                    fn execute(&mut self, op: &Op) -> Result<(), BackendError>; }
#[derive(thiserror::Error)] pub enum BackendError { #[error("{0}")] Storage(String), #[error("{0}")] Other(String) }
pub struct ApplyReport { pub completed: Vec<usize>, pub failed: Option<(usize, String)>, pub not_run: Vec<usize> }
pub fn apply(backend: &mut dyn Backend, queue: &[Op], ctx: &Context) -> ApplyReport;
```
Apply algorithm: snapshot → validate the whole queue (abort with `failed=(0, …)` if not `ok`) → for each operation: re-snapshot, check `DiskId` exists, execute, snapshot, compare with `project(before, op)`. Comparison is by partition offset; size within ±1 MiB; fs equal for Format and Create. Stop at the first error or mismatch.

Enumeration mapping:
- `MSFT_Disk`: `UniqueId`, `Number`, `FriendlyName`, `SerialNumber`, `Size`, `BusType`, `PartitionStyle`, `LogicalSectorSize`. `IsBoot || IsSystem` sets `is_running_os` (always false when `is_winpe()`).
