Snapdragon laptop says “no drive”: the complete guide

How to fix it, back it up and understand it, using the ASUS ProArt PZ13 (Snapdragon X, ARM64) as the worked example. Written for ordinary users; the technical detail is in clearly marked sections you can skip.

In one paragraph: Your laptop's settings screen (the BIOS) shows the SSD, but Windows Setup, diskpart, the ASUS recovery USB and ASUS Cloud Recovery all say there is no drive. On Snapdragon machines, Windows deliberately hides an internal SSD that holds only Qualcomm firmware partitions and no normal Windows partition. Nothing inside Windows can un-hide it, because Windows itself is doing the hiding. The fix is a small tool that runs before Windows starts and adds the normal Windows partitions back, leaving the firmware untouched. After that, Windows can see the drive and installs normally.

1. Is this your problem?

It very probably is if all of these are true:

  • The laptop or tablet has a Qualcomm Snapdragon processor (Snapdragon X Elite / X Plus, 8cx and similar). Windows calls these “ARM64” PCs.
  • The BIOS / UEFI setup screen (on ASUS, tap F2 at power-on) shows the SSD and its size.
  • Windows Setup says “We couldn't find any drives”, and no driver you load fixes it.
  • diskpart → list disk in a recovery or installer command prompt shows no internal disk, or the disk cannot be cleaned, formatted or written to.
  • The maker's own recovery tools (for ASUS: the recovery USB and Cloud Recovery) also see no storage.

It usually starts after the Windows partitions were deleted, for example with a partition tool or a reinstall that went wrong. The small Qualcomm firmware partitions survive, because they are protected, and that combination is what triggers the lock.

Not this problem if the BIOS does not show the SSD at all. That points to hardware (a loose or failed SSD), and nothing in this guide will help.

2. Why it happens

Snapdragon PCs keep some of their own firmware on the main SSD, in small partitions with names like NHLOS and UpdateCapsule. Windows protects these: on a Qualcomm machine, it treats any partition type it does not recognise as a “service” partition that ordinary programs must not touch.

The trap is a second rule. If an internal disk holds service partitions and no normal partition at all, Windows hides the whole disk and refuses every attempt to write to it. Setup, diskpart, the ASUS recovery image and Cloud Recovery all run on Windows, so all of them are blocked in the same way.

The way out is to write the partition table from outside Windows, from the UEFI firmware before Windows loads. Add even one normal partition and Windows stops hiding the disk. The fix tool adds the four standard Windows partitions in one go.

Technical detail (for the curious)

This was confirmed by disassembling the ARM64 partmgr.sys (Windows 11 26100). The partition manager reads the SMBIOS table, sees “Qualcomm”, and checks the licence value Kernel-OneCore-DeviceFamilyID. On a non-removable disk it marks partitions of unknown type as service partitions. When a disk has service partitions but no normal ones, it sets an internal flag (0x2000) that surfaces as DISK_ATTRIBUTE_HIDDEN (0x4), and it denies every write-type open, for data and for attribute changes. That is why even clearing the “hidden” attribute fails with access denied (Win32 error 5).

Ruled out along the way: a missing NVMe driver (the SSD uses Windows' inbox stornvme, the same stack ASUS's own recovery image uses), the Qualcomm QcSOCPartition driver, and Storage Spaces (both were disabled with no change). None of the 11 firmware type GUIDs are hard-coded in partmgr; the rule is generic.

3. What you need

  • Another Windows PC to prepare the USB sticks.
  • Stick 1, any size (even 1 GB): the gptfix tool.
  • Stick 2, 16 GB or larger: the installer (a mini-Windows called WinPE, plus the Windows image and the Qualcomm drivers).
  • Optional: a third drive (USB stick or external disk, exFAT or NTFS, at least 4 GB free) for backups.
  • The WoA Rescue Kit folder: Setup-RescueKit.ps1, 1-gptfix-stick\ and 2-winpe-stick\.
  • About 45 minutes, most of it waiting.
Each stick you prepare is completely erased. Copy anything you want off it first.

4. The fix, step by step

4.1 Build the two sticks (on the other PC)

  1. Unplug every USB drive you care about. Plug in Stick 1.
  2. In the WoA Rescue Kit folder, right-click Setup-RescueKit.ps1 → Run with PowerShell, and approve the administrator prompt.
  3. It lists only USB disks. Type the disk number, then type ERASE in capitals to confirm. Nothing is written until you do.
  4. When asked, plug in Stick 2 and repeat. Copying the Windows image takes a few minutes.

4.2 Un-hide the SSD (Stick 1, Secure Boot OFF)

  1. Turn the tablet off. Power it on and tap F2 to open the BIOS.
  2. Set Secure Boot = Disabled. Save and exit. (The gptfix tool is not signed by Microsoft, so Secure Boot would refuse to run it.)
  3. Plug in Stick 1 only and boot from it (F2 → boot menu → the USB).
  4. The tool lists the 11 firmware partitions it found and the 4 Windows partitions it will add (EFI, MSR, Windows, Recovery). Check that it shows the PZ13 SSD size line.
  5. Type YES and press Enter. Wait for DONE: verified. Both partition table copies are valid…, then press Enter to restart.
  6. Tap F2 again and set Secure Boot = Enabled. Save and exit.
gptfix is built to be safe. It writes nothing and says STOPPED unless it finds exactly the PZ13 disk size, a valid protective MBR, two matching and checksum-correct partition tables, the 11 PZ13 firmware partitions in their exact places, and either nothing else (it then adds the four Windows partitions) or exactly its own four (it then says they are already there). If someone has since repartitioned Windows, for example split C: into two drives, it stops rather than overwrite that.

4.3 Install Windows (Stick 2, Secure Boot ON)

  1. Unplug Stick 1, plug in Stick 2, and boot from it.
  2. The rescue menu opens on its own. (On an older stick it first asks “Type I and press Enter…”: type I.)
  3. Choose [1] Install Windows (clean) and type INSTALL when asked. It first saves a copy of the disk's partition table to woa-backup\ on the stick, then formats the EFI, Windows and Recovery partitions, applies Windows, writes the boot files, sets up the recovery environment, adds the Qualcomm drivers and restarts.
  4. Remove the stick when it restarts. Windows finishes its first-start set-up.

This was done on a real PZ13 on 7 November 2026 and completed a working clean install.

Once the laptop works, make a backup. If the disk is ever wiped or the firmware partitions are damaged, it lets you put the exact structure back from a non-booting state.

5.3 How to back up

  1. Boot Stick 2. Plug in the backup drive. It must not be the rescue stick.
  2. Choose [2] Back up the internal disk, type the backup drive's letter, then choose [1] Full or [2] Boot + firmware only.
  3. Each partition shows a live progress line such as NHLOS 100% (120 / 120 MiB). Large data partitions are reported as skipped; that is expected.
  4. Wait for BACKUP COMPLETE, then choose Shut down, Restart or Back to menu.
  5. Keep the whole pz13-image-… folder, ideally in two places.

5.4 How to restore (even when nothing boots)

  1. If every tool says “no drive” again, run Stick 1 (gptfix) first, with Secure Boot OFF. A wiped disk is hidden, and nothing can write to it until it is un-hidden.
  2. Boot Stick 2, choose [3] Restore, plug in the backup drive, pick the backup from the list, and type RESTORE.
  3. It writes back the exact partition table and every saved partition. If the backup holds windows.wim, it also re-applies Windows and repairs the boot files.
  4. For a boot + firmware backup, choose [1] Install Windows afterwards to put Windows back.
BitLocker / Device Encryption: the PZ13's EFI partition contains a BitLocker folder, so encryption may be switched on. A restore or firmware change can make Windows ask for the BitLocker recovery key. Find it now at aka.ms/myrecoverykey (your Microsoft account) and write it down.

6. The EFI system partition explained

The EFI system partition (ESP) is a small FAT32 partition that the firmware reads when the laptop powers on. It holds the programs that start Windows, and the list (BCD) of what to start. Without it, Windows is still on the disk but nothing starts it.

On the PZ13 it is 260 MiB, of which about 104 MB is used, in 117 files. Its contents, taken from the real backup:

If the ESP is damaged: Windows' boot files can be rebuilt from Stick 2's command prompt with bcdboot W:\Windows /s S: /f UEFI (W: = Windows, S: = the ESP). That does not bring back Persisted_Capsules.bin, and that is one reason to restore the ESP from your backup instead.

Secure Boot and signatures: Snapdragon X firmware (2024 onwards) trusts boot files signed by the newer Windows UEFI CA 2023 certificate, and the PZ13 also still accepts the older PCA 2011 one. The rescue stick's WinPE is signed with the 2023 certificate, so it boots with Secure Boot on. Only the gptfix tool needs Secure Boot off.

8. Other Snapdragon devices

The cause applies to every Snapdragon Windows PC: an internal disk with only firmware partitions is hidden, and adding a normal partition from outside Windows releases it. The PZ13 numbers do not apply anywhere else. Other models have different firmware partitions, sizes and positions.

Do not run the PZ13 gptfix on another model. It is designed to stop on any other disk, but nothing about another device's layout has been tested. Do not delete, “clean” or reformat the firmware partitions on any Snapdragon PC either: Windows cannot recreate them.

To adapt the method to another device, someone technical needs to:

  1. Read the device's real partition table (both GPT copies) without writing anything, and save a copy.
  2. Note where the firmware partitions end, and plan EFI (≥ 260 MiB), MSR (16 MiB), Windows and Recovery (1 GiB, attributes 0x8000000000000001) in the free space after them, aligned to 1 MiB.
  3. Write the new entries from UEFI (not from Windows), updating both GPT copies and their checksums, and leaving every existing firmware entry byte-identical.
  4. Test on a virtual disk of exactly the same size first. That is how the PZ13 tool was rehearsed before it touched real hardware.

The source code for the PZ13 tools (gptfix, the installer and the backup tool) is in the WoA Rescue Kit project and can serve as a template.

11. Glossary

ARM64The processor family used by Snapdragon PCs. Needs ARM64 versions of Windows and drivers.
BIOS / UEFIThe firmware that runs before Windows. UEFI is the modern kind; “BIOS” is the everyday name for its settings screen.
Secure BootA UEFI setting that only starts programs signed by trusted keys.
GPTGUID Partition Table: the list of partitions at the start of the disk, with a second copy at the end.
PartitionA slice of the disk. Each has a start, a size, a type (GUID) and attributes.
LBA / sectorA 512-byte block of the disk, numbered from 0. 1 MiB = 2,048 sectors.
MiB / GiB1 MiB = 1,048,576 bytes; 1 GiB = 1,024 MiB. Disk makers' “GB” are 1,000,000,000 bytes.
ESPEFI system partition: the boot partition (section 6).
MSRMicrosoft Reserved partition: a small empty area Windows keeps for itself.
WinPEWindows Preinstallation Environment: a mini-Windows that runs from a USB stick.
WIMWindows Imaging format: a compressed file holding a whole Windows installation (install.wim, boot.wim, windows.wim).
DISMMicrosoft's tool for capturing and applying WIM images.
NHLOSQualcomm's term for firmware that does not run on the main operating system (“non-high-level OS”).
partmgrWindows' partition manager driver: the part that hides the disk.
